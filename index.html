怎麼玩

畫面上是一張有權重的地圖：圓圈是地點（節點），連線是道路（邊），線上的數字是走那段路要花的時間（權重）。每個節點上方的數字，是「目前已知最快幾分鐘能到這裡」——開始除了起點是 0，其他全是 ∞（還不知道怎麼去）。

你會學到什麼

  • 為什麼 BFS 在加權圖上會答錯——邊數最少 ≠ 總時間最短。第 2 關就是專門設計來讓 BFS 出糗的反例。
  • 優先佇列是什麼——一種「永遠讓最小的排最前面」的候位名單。把 Queue 的普通佇列換成它，BFS 就升級成 Dijkstra。
  • 鬆弛（relax）——「發現更快的走法就更新筆記」，這個動作的正式名字。整個演算法就是不停地鬆弛。
  • lazy deletion（過期條目）——dist 被更新後，佇列裡的舊條目不用刪，取出時認出它過期、跳過就好。
  • 貪心為什麼是對的——為什麼被取出的節點 dist 就此定案、永不再變。
  • 負權重為什麼會壞掉——Dijkstra 的保證建立在「路只會越走越長」上。
  • 複雜度 O((V+E) log V)——log 是優先佇列收的手續費。
建議順序

先用演示模式走完第 1 關教學小圖（會遇到兩次過期條目），再玩第 2 關 BFS 陷阱圖看清楚為什麼要升級佇列，最後切闖關模式挑戰第 3 關。

THE IDEA IN CODE

核心只有四件事。

O((V + E) log V)
dijkstra.jsPSEUDOCODE
// 1. 起點距離設為 0，其餘設為無限大
dist[start] = 0
pq.push((0, start))

while pq is not empty:
    (d, u) = pq.pop_min()
    if d > dist[u]: continue  // 2. 跳過過期條目

    for each edge (u, v, weight):
        candidate = dist[u] + weight
        if candidate < dist[v]:     // 3. 鬆弛：找到更短的路
            dist[v] = candidate
            parent[v] = u
            pq.push((candidate, v)) // 4. 放入新的候選距離

每次取出最小距離，然後把更好的可能性放回佇列。就這麼簡單，直到所有最短路徑都浮現。
